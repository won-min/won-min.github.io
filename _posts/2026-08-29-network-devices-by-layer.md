## 요약

1.  장비의 계층은 "데이터의 어떤 정보를 보고 판단하느냐"로 나뉜다.
2.  보는 정보는 X → MAC → IP → IP+포트+부하 상태로 올라간다.
3.  보안 담당자가 각 장비가 어떤 기능을 제공하고, 그 장비로 어떤 정책을 반영할 수 있는지를 미리 알고 있어야 정책의 적정성을 판단할 수 있다.

## 1계층 — 케이블 · 리피터 · 허브

### 케이블

케이블은 **신호가 지나가는 물리적 통로**다. 종류에 따라 간섭에 얼마나 강한지, 얼마나 멀리 가는지가 다르다.

<table>
<tbody>
<tr><td>UTP</td><td>구리선을 두 가닥씩 꼬아 간섭을 줄임</td><td>저렴, 얇고 유연해 배선이 쉬움</td><td>노이즈 환경에 약함</td><td>가정·사무실 LAN</td></tr>
<tr><td>STP</td><td>UTP에 차폐를 더함</td><td>전자기 간섭에 강함</td><td>비싸고 두꺼워 시공이 까다로움</td><td>발전소, 변전소, 철도</td></tr>
<tr><td>동축 케이블</td><td>중앙 도체를 차폐층이 감쌈</td><td>꼬임쌍선보다 대역폭이 넓고 노이즈에 강함</td><td>무겁고 구부리기 어려움</td><td>케이블 TV, 케이블 인터넷</td></tr>
<tr><td>광섬유</td><td>빛으로 전송</td><td>장거리·고대역폭, 간섭 거의 없음</td><td>비용이 높음</td><td>통신사 백본, 해저 케이블</td></tr>
</tbody>
</table>

이때, 거리가 멀어질수록 신호가 약해지는 감쇠현상 때문에 리피터가 필요하다.

### 리피터

**케이블을 지나며 약해진 신호를 원래의 0과 1 형태에 가깝게 복원해서 다시 보내는 장비**다.<br>
디지털 리피터는 세 가지를 수행한다.

- Re-amplify: 신호의 세기를 키움
- Re-shape: 파형을 0/1로 판정해 각지게 세움
- Re-time: 밀린 전환 시점을 클럭에 맞춰 정렬

리피터는 프레임이나 패킷을 이해하지 않는다.<br>
요즘은 2계층 스위치·브리지가 리피터 기능을 포함하는 경우가 대부분이라 단독으로 쓰는 경우는 줄어들고 있다.

### 허브

**한 포트로 들어온 신호를 나머지 모든 포트에 뿌리는 장비**다.<br>
멀티포트 리피터라고도 부른다.<br>
허브는 하나의 케이블로 들어온 신호를 여러 명이 나눠 쓸 수 있게 해주지만, 문제가 있다.

- 충돌: 두 대가 동시에 전송하면 신호가 엉킨다. 충돌 상황에 대한 별도 제어 기능이 없어서, 장비 수와 부하가 늘수록 충돌 확률이 급격히 높아지고 속도가 느려진다.
- 대역폭 공유: 100Mbps 허브에 10대가 물려 있으면 10대가 100Mbps를 나눠 쓴다.
- 보안 부재: 모든 포트로 신호를 뿌리므로, 허브에 연결된 PC가 다른 사람의 통신 내용을 전부 볼 수 있다.

이 단점을 2계층 장비에서 보완한다.

## 2계층 — 브리지 · 스위치

### 동작 원리

브리지와 스위치는 **프레임이 도착하면 헤더에서 목적지 주소(이더넷 48비트 MAC)를 뽑아 테이블에서 조회하고, 어느 포트로 보낼지 결정**한다.

- **브리지**: 네트워크 구간을 연결하며 MAC 기준으로 프레임을 통과/차단
- **스위치**: 브리지를 다수 포트 + 하드웨어 처리로 확장한 장비

둘 다 스위치 테이블(MAC 주소, 인터페이스, 기록 시각)로 판단한다.

### 자가학습

**스위치 테이블을 스스로 채우는 과정**이 자가학습이다.

<table>
<tbody>
<tr><td>Learning</td><td>들어온 프레임의 출발지 MAC + 도착 포트 + 시각을 테이블에 기록</td></tr>
<tr><td>Flooding</td><td>목적지 MAC이 테이블에 없으면 들어온 포트를 제외한 모든 포트로 내보냄</td></tr>
<tr><td>Forwarding</td><td>목적지 포트와 출발 포트가 다르면 그 포트로만 전달</td></tr>
<tr><td>Filtering</td><td>목적지 포트와 출발 포트가 같으면 폐기. 이미 그 세그먼트에 브로드캐스트됐기 때문</td></tr>
<tr><td>Aging</td><td>일정 시간(aging time) 동안 프레임을 보내지 않은 항목은 삭제</td></tr>
</tbody>
</table>

### 브리지 vs 스위치

|             | 브리지                                | 스위치                                                          |
|-------------|---------------------------------------|-----------------------------------------------------------------|
| 동작 원리   | 목적지 MAC 조회                       | 동일                                                            |
| 포트 수     | 5~10개 미만 (허브와 큰 차이 없음)     | 10개 이상 ~ 50개 (가격에 따라 천차만별)                         |
| 포트별 속도 | 모든 포트가 동일한 속도               | 포트별 속도 제어·통제 가능                                      |
| 처리 방식   | 소프트웨어 → 느림                     | ASIC 하드웨어 → 빠름                                            |
| 전송 방식   | Store and Forward (전부 저장 후 전송) | 주로 Cut-through (들어오는 대로 전송), Store and Forward도 지원 |

스위치가 브리지보다 가격이 많이 비싸서 비용 문제로 브리지를 쓰는 곳을 제외하면, 실무 네트워크 인프라는 거의 대부분 스위치로 구성한다.

## 3계층 — 라우터

### 라우팅

라우팅이란 **서로 다른 네트워크 사이에서 목적지 IP 주소를 보고 패킷이 목적지까지 갈 경로를 정하는 일**이다. 스위치가 같은 네트워크 안의 길을 찾는다면, 라우터는 다른 네트워크로 가는 길을 찾는다.

```text
패킷 수신 → 목적지 IP 확인 → 라우팅 테이블에서 가장 일치하는 경로 검색 → 다음 홉으로 전달
```

### 라우팅 테이블

테이블에 40억 개 IPv4 주소를 다 적을 수는 없기 때문에 프리픽스(CIDR)로 집약해 항목 수를 줄인다. 여러 항목이 매치되면 **가장 긴 프리픽스**(가장 구체적인 경로)를 사용한다.

<table>
<tbody>
<tr><td>11001000 00010111 00010</td><td>21비트</td><td>0</td></tr>
<tr><td>11001000 00010111 00011000</td><td>24비트</td><td>1</td></tr>
<tr><td>11001000 00010111 00011</td><td>21비트</td><td>2</td></tr>
<tr><td>그 외 (Otherwise)</td><td>0비트</td><td>3</td></tr>
</tbody>
</table>

예를 들어 목적지가 11001000 00010111 00011000 10101010이면 앞 21비트는 3번째 항목(링크 2)과, 앞 24비트는 2번째 항목(링크 1)과 일치한다. 둘 다 매치되면 더 긴 24비트 쪽인 링크 1을 선택한다.

### 정적 라우팅 vs 동적 라우팅

라우팅 방식은 크게 정적 라우팅과 동적 라우팅으로 구분된다.<br>
관리자가 수동으로 라우팅을 설정하지 않는 이상, 라우터는 보통 기본적으로 동적 라우팅으로 동작한다.

|             | 정적 라우팅                                          | 동적 라우팅                                                                                       |
|-------------|------------------------------------------------------|---------------------------------------------------------------------------------------------------|
| 채우는 주체 | **관리자가 직접 입력**                               | **라우팅 프로토콜이 이웃과 정보를 교환해 자동 학습** (RIP, OSPF, EIGRP, BGP)                      |
| 경로 변화   | 사람이 개입할 때만                                   | 트래픽 부하·토폴로지 변화에 따라 주기적으로 또는 즉시 변경                                        |
| 장비 부하   | CPU·대역폭 사용 X                                    | 제어 메시지 교환과 계산에 CPU·대역폭 소모. 경로 변경이 너무 빈번하면 라우터 기능이 마비될 수 있음 |
| 장애 대응   | 수동. 링크가 죽어도 테이블은 그대로                  | 자동. 장애·혼잡을 피해 재계산                                                                     |
| 적합 규모   | 소규모, 단순 토폴로지, 출구가 하나뿐인 stub 네트워크 | 복잡하고 빠르게 바뀌는 대규모 토폴로지                                                            |
| 위험        | 설정 실수가 그대로 남음, 규모 확장 불가              | 라우팅 루프와 경로 진동에 취약                                                                    |

### LS vs DV, 그리고 AD

동적 라우팅 방식에는 링크 상태와 거리 벡터가 있다.

- **LS (링크 상태, 예: OSPF)**: 모든 노드가 자기 링크의 상태·비용을 전체에 브로드캐스트한다. 각자 전체 지도를 갖고 스스로 최단 경로를 계산한다(Dijkstra). 모두가 동일한 지도를 가진다.
- **DV (거리 벡터, 예: RIP)**: 처음엔 직접 연결된 링크 비용만 아는 상태에서 이웃과 반복 교환하며 점진적으로 계산한다. 전체 지도 없이 이웃이 알려준 거리만 사용한다(Bellman-Ford).

메트릭은 프로토콜마다 정의가 달라서 서로 다른 프로토콜이나 정적 설정에서 온 경로끼리는 메트릭으로 비교할 수 없다. 그래서 외부 기준이 필요한데, 그것이 **AD(Administrative Distance)** 다. AD가 낮을수록 신뢰할 만한 출처로 보고 그 경로를 사용한다. 이것은 표준이 아니라 Cisco 벤더 구현 개념이다.

## 4계층 — 로드밸런서

### 부하분산

스위치가 4계층에서 동작할 때 로드밸런싱 역할을 수행한다고 보면 된다.<br>
**부하분산이란 서버 한 대의 성능에는 한계가 있으니 서버를 여러 대 두고, 클라이언트는 단일 목적지 IP로 접속하게 한 뒤 앞단의 로드밸런서가 요청을 나눠 주는 것**이다. 외부 요청은 전부 먼저 로드밸런서로 가고, 로드밸런서는 각 호스트의 현재 부하에 따라 분배한다. 이때 목적지 IP뿐만 아니라 포트 번호(4계층)까지 보고 판단한다.

### L4 vs L7

|             | NLB                                        | ALB                                                 |
|-------------|--------------------------------------------|-----------------------------------------------------|
| 계층        | 4계층 (전송)                               | 7계층 (응용)                                        |
| 판단 정보   | IP 주소 + 포트 번호, 서버 가용성           | HTTP 헤더, URL 경로, 쿠키, SSL 세션 ID 등 요청 내용 |
| 프록시 동작 | 연결을 끊지 않고 흐름 단위 전달            | 클라이언트 연결을 종료하고 새 연결 (프록시)         |
| 적합 용도   | 고성능·저지연·대규모 (게임, 스트리밍, IoT) | 마이크로서비스, 컨테이너, 웹앱                      |

### 분산 알고리즘

로드밸런서는 분산 알고리즘에 따라서 요청을 뒤쪽 서버로 전달한다.

|                 | 방식                                          | 한계 / 특징                                                                                                           |
|-----------------|-----------------------------------------------|-----------------------------------------------------------------------------------------------------------------------|
| 라운드로빈      | 서버를 차례로 돌아가며 선택                   | 요청마다 비용이 다르고 서버 성능도 달라 서버 간 부하량 차이가 크게 벌어질 수 있음                                     |
| 최소 연결       | 활성 연결 수가 가장 적은 서버로 전달          | 느린 서버의 부하가 자연히 줄어듦. 다만 고장나서 에러만 빨리 돌려주는 서버가 '여유 있음'으로 보여 트래픽이 몰리는 문제 |
| 가중 라운드로빈 | 서버마다 가중치(성능·이용률)를 두어 비율 조정 | 라운드로빈의 개선판                                                                                                   |
| 해시            | 클라이언트 IP나 키를 해시해 서버 결정         | 균등 분산이 아니라 같은 클라이언트를 같은 서버에 붙이는 세션 고정 목적                                                |

## 정리

장비의 계층은 **"데이터의 어떤 정보를 보고 판단하느냐"**로 나뉜다. 리피터·허브는 주소를 안 보고 신호만 전달하고, 브리지·스위치부터 판단이 시작된다. 보는 정보는 MAC → IP → IP+포트+부하 상태로 올라간다.

|                     | 리피터 / 허브                   | 브리지 / 스위치                      | 라우터                                                        | 로드밸런서                                            |
|---------------------|---------------------------------|--------------------------------------|---------------------------------------------------------------|-------------------------------------------------------|
| 역할                | 주소를 안 보고 신호만 전달·복원 | MAC 주소를 보고 같은 LAN 안에서 전달 | IP 주소와 라우팅 테이블을 보고 다른 네트워크로 갈 경로를 정함 | IP + 포트 + 프로토콜을 보고 여러 서버로 트래픽을 나눔 |
| 판단 여부           | X                               | O                                    | O                                                             | O                                                     |
| 판단 정보           | 전압 상태                       | MAC 주소                             | IP 주소                                                       | IP + 포트 번호 + 부하 상태                            |
| 충돌 도메인         | 못 나눔 (전체가 하나)           | 구간·포트별 분리                     | 분리                                                          | 분리                                                  |
| 브로드캐스트 도메인 | 못 나눔                         | 못 나눔 (VLAN 필요)                  | 분리                                                          | 분리                                                  |
