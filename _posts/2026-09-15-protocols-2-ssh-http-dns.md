## 요약

- Telnet과 SSH는 둘 다 원격 접속에 사용되지만, 평문인지 암호화된 통로를 사용하는지가 다르다.
- HTTPS는 TLS(SSL)에 평문 전송 기반인 HTTP를 올린 것이다.
- DNS는 사람이 기억하기 쉬운 호스트명을 고정 길이 IP 주소로 변환하는 서비스이다

---

## Telnet

### Telnet이란

Telnet은 **원격 시스템의 가상 터미널에 접속하기 위한 클라이언트–서버 응용 계층 프로토콜**이다.

1969년 ARPANET용으로 개발되었고, **TCP 23번 포트**를 사용한다.

![Telnet이란](01.png){: w="600" h="273" }

사용 방법이 간단하고, 운영체제에 종속되지 않아 다양한 OS에서 사용 가능하다는 장점이 있지만, 평문 전송·서버 인증 부재·무결성 검증 부재와 같은 이유로 **현재 SSH로 대체**되었다.

현재는 피치 못할 사정으로 레거시 장비에서 사용되거나, 포트 연결 테스트 등에 제한적으로 사용되고 있다.

## SSH

### SSH란

SSH는 안전하지 않은 네트워크 위에서 **안전한 원격 로그인과 기타 보안 네트워크 서비스를 제공하는 프로토콜**이다.

기본적으로 **TCP 22번 포트**를 사용한다.

![SSH란](02.png){: w="654" h="317" }

1995년 Tatu Ylönen이 대학 네트워크에서 발생한 비밀번호 스니핑 사건을 계기로 개발되었고, Telnet·rsh·rlogin·rexec처럼 평문으로 인증·통신하는 프로토콜의 대체재로 설계되었다.

SSH 프로토콜의 구조는 아래와 같다.

- **transport layer 프로토콜**: 서버 인증, 무결성, 완전 순방향 비밀성(PFS)을 갖춘 기밀성을 제공
- **user authentication 프로토콜**: 서버에 대해 클라이언트를 인증
- **connection 프로토콜**: 암호화된 터널을 여러 개의 논리 채널로 다중화

그리고, SSH가 제공하는 보안 네트워크 서비스의 예시는 아래와 같다.

- interactive shell: 원격 컴퓨터에 로그인해 명령어를 입력
- TCP/IP port forwarding(터널링): 다른 프로토콜의 통신(예: DB 접속 3306)을 SSH 통로 안에 넣어 보호
- X11 forwarding: 원격 컴퓨터에서 실행되는 GUI 프로그램을 로컬 컴퓨터에 표시
- subsystem: 서버에 이름으로 미리 등록된 서비스를 호출, 예: SFTP


### SSH 연결 수립과 인증

![SSH 연결 수립과 인증](03.png){: w="629" h="397" }

**서버가 제공한 호스트 키를 판정하는 방법**은 두 가지이다.

- 클라이언트가 로컬 DB에 접속할 서버들의 키를 직접 보관한다. 이때 TOFU(Trust On First Use), 즉 호스트에 처음 접속할 때만 검증 없이 호스트 키를 수용하는 방식이 사용된다.
- CA 인증서를 통해 인증한다.

**키 교환(Diffie-Hellman / ECDH)** 은 양쪽이 각자 값을 만들어 교환하고, 받은 값과 자기 개인값을 결합해 같은 secret에 도달하는 방식이다. secret 자체는 네트워크로 오가지 않는다.

**사용자 인증 방식**은 아래와 같다.

- **password**: 비밀번호를 그대로 서버에 보내 확인받는 가장 단순한 방식
- **publickey**: 클라이언트가 세션 식별자 등을 개인키로 서명해 보내고, 서버는 authorized_keys에 등록된 공개키로 검증하는 방식
- **keyboard-interactive**: 서버가 임의의 질문을 보내고 클라이언트가 답을 받아 돌려주는 방식
- **GSSAPI**: 기업 SSO 환경에서 주로 사용. 사용자가 도메인에 로그인하면서 이미 티켓을 받아둔 상태라면 해당 티켓을 인증에 사용


### SSH를 이용하는 대표적인 Tool

- **OpenSSH**: Linux·macOS 기본 탑재 SSH 클라이언트/서버
- **PuTTY**: Windows에서 널리 사용되는 대표적인 SSH 접속 도구
- **WinSCP**: SSH 기반 SFTP/SCP 파일 전송 도구
- **MobaXterm**: Windows용 통합 터미널
- **Termius**: PC·모바일에서 SSH 접속을 관리하는 도구
- **VS Code Remote-SSH**: 원격 서버에 접속해 로컬처럼 코드를 편집·디버깅하는 도구

## HTTP

### HTTP의 특징

HTTP는 **분산·협업 하이퍼미디어 정보 시스템을 위한 응용 계층 프로토콜**로, World Wide Web 데이터 통신의 기반이다. **기본 포트는 80**이다.

브라우저가 페이지의 객체(HTML, CSS, JS, JPEG 등)마다 요청 메시지를 보내고, 서버가 응답 메시지로 객체를 반환하는 방식으로 동작한다.

**무상태(Stateless)** 프로토콜이라 서버는 클라이언트 상태를 저장하지 않는다. 세션이 필요하면 쿠키 등 응용 수준에서 구현한다.

그리고, **신뢰성 있는 전송 위에서 동작**한다.

- HTTP/1.0, 1.1, 2는 TCP
- HTTP/3는 QUIC (UDP 위에서 신뢰성을 직접 제공)


### HTTP 메서드, 상태 코드

주로 사용되는 **HTTP 메서드**는 아래와 같다.

| 메서드      | 의미             |
|-------------|------------------|
| GET         | 자원 조회        |
| POST        | 데이터 전송/생성 |
| PUT / PATCH | 전체 / 일부 수정 |
| DELETE      | 자원 삭제        |

주로 사용되는 **상태 코드**는 아래와 같다.

| 코드 | 의미                                |
|------|-------------------------------------|
| 2xx  | 성공                                |
| 3xx  | 리다이렉션. 다른 URL 또는 캐시 참조 |
| 4xx  | 클라이언트 오류                     |
| 5xx  | 서버 오류                           |

## HTTPS

### HTTPS의 특징

HTTP는 암호화가 없기 때문에 도청과 중간자 공격에 취약하다.

이를 해결하기 위해 일반 **HTTP를 TLS(과거 SSL) 위에서 사용하는 것이 HTTPS**이다. **포트는 443**을 사용한다.

TLS가 제공하는 보안 목표는 세 가지이다.

- **인증**: 접속한 웹사이트가 진짜인지 X.509 인증서와 CA(인증 기관)로 검증
- **기밀성**: 전송 데이터를 암호화하여 도청을 방지
- **무결성**: 전송 중 변조를 탐지

로그인 페이지, 마이페이지처럼 중요한 정보를 다루는 페이지는 그 페이지가 가진 정보 자체가 중요하고 노출되어선 안 되므로 HTTPS를 의무로 적용해야 한다.

그리고, TLS는 현재 1.3 버전까지 나와있는데 통상적으로 1.2 이상부터 안전한 방식으로 적용했다고 본다.


### HTTPS 연결 수립 - TLS 핸드셰이크

![HTTPS 연결 수립 - TLS 핸드셰이크](04.png){: w="609" h="484" }

각 메시지에 담기는 내용은 아래와 같다.

- **Client Hello**: 버전, 암호 스위트 후보, 논스, DH 공개값
- **Server Hello**: 서버 인증서(CA가 서명한 X.509), 선택한 암호 스위트, 서버의 논스, 서버의 DH 공개값
- **Server/Client Finished**: 지금까지 오간 핸드셰이크 메시지 전체에 대한 MAC 값. 이것을 검증하여 메시지 변조를 탐지

마스터 시크릿은 상대의 DH 공개값과 자신의 DH 개인값을 가지고 각자 계산한다.

## DNS

### DNS의 특징

DNS는 사람이 기억하기 쉬운 **호스트명을 고정 길이 IP 주소로 변환하는 서비스**이다.

동시에 DNS 서버 계층으로 구현된 **분산 데이터베이스**이자 그 DB를 질의하는 **응용 계층 프로토콜**을 의미하기도 한다.

ARPANET의 hosts.txt 방식이 규모·이름 충돌 문제에 부딪히면서 1983년 도입되었다.

기본적으로 **UDP 53번 포트**를 사용한다. 다만, 긴 응답이나 존 전송처럼 **데이터 크기가 큰 경우에는 TCP 53**을 이용한다.

DNS의 특징은 아래와 같다.

- **계층적**: 도메인 이름은 트리 구조로 이루어짐. www.example.com은 오른쪽부터 root → com → example → www 순으로 읽음.
- **분산 구조**: 단일 장애 지점을 없애기 위해 분산으로 설계
- **권한 위임**: 도메인마다 권한 네임서버를 지정하고, 하위 도메인은 다시 위임
- **TTL 캐싱**: 조회 결과를 TTL 동안 저장해 반복 질의 시 빠르게 응답


### DNS 서버 유형

- **Local DNS (Resolver)**: 사용자가 가장 먼저 질의하는 서버. 사용자를 대신해 끝까지 찾아주고 결과를 캐싱
- **Root DNS**: 계층 최상위. 13개 루트 서버 네트워크(A~M)를 독립 기관들이 운영하며, 해당 TLD 서버의 위치를 안내
- **TLD DNS**: .com, .net, .kr 등 최상위 도메인을 담당. 해당 도메인의 권한 서버 위치를 안내
- **Authoritative DNS**: 특정 도메인의 실제 레코드를 보유하고 최종 IP를 응답


### DNS 작동 원리

![DNS 작동 원리](05.png){: w="551" h="525" }

쿼리 유형은 두 가지이다.

- **재귀 질의**: 클라이언트가 하나의 서버에 물으면, 그 서버가 끝까지 대신 찾아 완전한 답을 돌려주는 방식
- **반복 질의**: 서버가 답을 모르면 참조만 돌려주고, 질의자가 계속 다음 서버에 묻는 방식


### 주요 리소스 레코드

**레코드는 (Name, Value, Type, TTL) 4-튜플 구조**이다.

| Type  | 의미 (Name -\> Value)           |
|-------|---------------------------------|
| A     | 호스트명 → IPv4 주소            |
| AAAA  | 호스트명 → IPv6 주소            |
| NS    | 도메인 → 권한 네임서버 호스트명 |
| CNAME | 별칭 → 정식(canonical) 호스트명 |
| MX    | 도메인 → 메일 서버 정식 이름    |
