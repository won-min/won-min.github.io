## 요약

- 방화벽은 내부망과 외부망 사이에서 보안 정책에 따라 트래픽을 허용·차단한다.
- DoS/DDoS는 허용된 방식을 과도하게 사용해 자원을 소진시키는 공격이라 방화벽만으로는 막기 어렵고, 여러 위치에서 공격을 완화한다.
- IDS와 IPS는 탐지 기술은 같지만, 배치와 탐지 이후의 행동이 다르다.

## 방화벽

### 방화벽이란

**방화벽은 신뢰하는 내부 네트워크와 신뢰할 수 없는 외부 네트워크 사이에서, 보안 정책에 따라 트래픽을 감시·제어하는 네트워크 보안 시스템**이다.

![방화벽이란](01.png){: w="436" h="239" }

조직이 LAN을 인터넷에 연결하면서 외부에서도 내부 네트워크에 접근할 수 있게 되었고, 이에 따라 외부 위협으로부터 내부를 보호해야 할 필요가 발생했다. 그런데 수많은 시스템이 서로 다른 OS·버전을 쓰는 조직에서 취약점마다 개별로 패치하는 것은 비효율적이다. 그래서 내부망과 인터넷 사이에 단일 통제 지점(single choke point)을 만들어, 취약한 서비스로의 접근을 한 곳에서 차단하고 보안 정책과 감사를 강제하게 되었다.

**방화벽이 제대로 기능하기 위한 전제**는 아래와 같다.

- 내부↔외부의 모든 트래픽은 반드시 방화벽을 통과해야 한다.
- 방화벽은 보안 정책이 인가한 트래픽만 통과시킨다.
- 방화벽 자체가 침투에 면역이어야 한다.

### 방화벽 접근 정책

**접근 정책의 필터링 기준**은 아래와 같다.

- IP 주소·프로토콜: 출발지·목적지 주소, 포트, 인바운드/아웃바운드 방향, 프로토콜 종류 등
- 애플리케이션 프로토콜: 패킷 안에 담긴 애플리케이션 계층 메시지의 내용이 허가된 것인지
- 사용자 신원: IPsec 등 보안 인증으로 식별된 사용자
- 네트워크 활동: 요청 시각, 요청률 등의 활동 패턴

**기본 정책(default policy)**은 어떤 정책에도 해당하지 않는 트래픽을 처리하는 방식이다.

- Default = discard: 명시적으로 허용되지 않은 것은 금지. 안전하지만 불편하며, 기업·정부가 선호
- Default = forward: 명시적으로 금지되지 않은 것은 허용. 편리하지만 위험하며, 대학 등 개방 조직이 선호

### 방화벽의 유형

방화벽은 어디까지 볼 수 있는지에 따라 유형이 나뉜다.

| 유형                    | 무엇인가                                                                                 | 해결한 한계                                                                                                                                    | 남은 한계                                                                                         |
|-------------------------|------------------------------------------------------------------------------------------|------------------------------------------------------------------------------------------------------------------------------------------------|---------------------------------------------------------------------------------------------------|
| 패킷 필터링             | 각 IP 패킷을 독립적으로 검사해 출발지·목적지 IP, 포트, 프로토콜만으로 통과·폐기를 결정   | 호스트마다 개별로 패치·보안을 강화하던 방식을 대신해 단일 통제 지점을 세움                                                                     | 패킷 하나만 보므로 연결 맥락을 모름. 응답을 받으려면 고번호 포트(1024 이상)를 넓게 열어야 함      |
| 상태 검사               | 진행 중인 연결을 상태 테이블에 기록하고 그 맥락에서 판단                                 | 아웃바운드 연결 목록에 부합하는 패킷만 들여보내, 고번호 포트를 통째로 열어야 하던 문제를 제거                                                  | 페이로드를 보지 않음. 허용된 포트(80, 443 등) 안의 공격은 그대로 통과. 사용자 신원 기반 통제 불가 |
| 애플리케이션 게이트웨이 | 종단 간 연결 없이 게이트웨이가 양쪽에 두 개의 연결을 맺고 애플리케이션 계층에서 중계     | 애플리케이션 계층 데이터와 사용자 신원까지 검사해, 헤더만 보는 필터로는 불가능했던 통제를 가능하게 함                                          | 앱마다 별도의 게이트웨이가 필요. 모든 데이터가 경유하므로 연결마다 처리 부하가 추가               |
| NGFW                    | 전통 방화벽(패킷 필터링, 상태 검사 등) + 인라인 DPI를 수행하는 애플리케이션 방화벽 + IPS | 앱마다 프록시를 두지 않고도 모든 트래픽의 페이로드를 검사. 웹 앱이 모두 80·443을 쓰면서 무의미해진 포트 기반 통제를 앱·사용자 단위 통제로 대체 | 성능 저하, 설정 복잡성. 시그니처가 없는 제로데이는 탐지 못 함. 회선을 포화시키는 DDoS는 방어 불가 |

\*인라인 DPI: 통신 경로 위에서 패킷 내부(페이로드)를 검사하는 기술

\*시그니처: 알려진 공격의 특징

\*제로데이: 알려지지 않은 취약점

### DMZ

**DMZ는 외부에 공개해야 하는 서버를 내부망에서 분리해 둔 중간 영역**으로, 인터넷과 사설망 사이에 놓인 작은 격리 네트워크이다.

DMZ의 목적은 침해 자체를 막는 것이 아니라, 공개 서버가 침해되더라도 내부망으로 번지지 않게 침해의 범위를 가두는 것이다.

- DMZ에 두는 것: 외부 연결성이 필요한 시스템. 웹 서버, 메일 서버, DNS 서버
- 내부망에 두는 것: 외부에서 직접 접근할 이유가 없는 시스템. 애플리케이션 서버, DB 서버, 직원 워크스테이션

구축 방식은 두 가지이다.

![단일 방화벽 DMZ](02.png)
_단일 방화벽 DMZ_

![이중 방화벽 DMZ](03.png)
_이중 방화벽 DMZ_

- 단일(three-legged): 인터페이스 3개(외부 / 내부 / DMZ)를 가진 방화벽 1대를 두는 구조. 구성은 단순하지만 방화벽이 단일 장애점이 되고, DMZ와 내부망 트래픽을 모두 감당해야 한다.
- 이중(back-to-back): 전면·후면 방화벽 2대 사이에 DMZ를 배치하는 구조. 공격이 성공하려면 두 장비를 모두 침해해야 하므로 더 안전하지만 구매·관리 비용이 증가한다.

### 방화벽의 한계

**방화벽을 거치지 않는 경로는 통제하지 못한다.**

- 방화벽을 우회하는 공격
- 직원 등 내부 위협
- 외부에서 감염되어 반입된 장비

그리고 **허용된 것처럼 보이는 트래픽 속의 공격은 완전히 막지 못한다.**

- 전통적 방화벽(패킷 필터, 상태 검사)은 443을 열면, 그 포트로 들어오는 공격도 통과시킨다.
- 애플리케이션 게이트웨이와 NGFW도 암호화 트래픽, 시그니처가 없는 제로데이, 형식상 정상인 공격은 놓칠 수 있다.

## DoS와 DDoS

### DoS/DDoS란

**DoS는 과도한 요청 등의 방법으로 자원을 소진시켜, 정상 사용자가 서비스를 이용하지 못하게 만드는 공격**이다.

**DDoS는 다수의 침해된 시스템(좀비)을 봇넷으로 묶어 동시에 공격하는 것**이다. 단일 시스템이 만들 수 있는 트래픽에는 한계가 있고 단일 출처는 상위 라우터가 쉽게 차단하므로, 공격이 분산 방식으로 진화한 결과이다.

| 항목      | DoS                                                   | DDoS                                                    |
|-----------|-------------------------------------------------------|---------------------------------------------------------|
| 공격 출처 | 단일 또는 소수의 시스템                               | 다수의 시스템                                           |
| 규모      | 생성 트래픽이 매우 제한적                             | 다수 시스템의 대역폭이 합쳐져 테라비트/초 규모까지 가능 |
| 대응      | 단일 출처 차단이 효과적. 상위 라우터가 탐지·차단 가능 | 개별 IP 차단으로 불충분. 통신사·클라우드 상위망 필요    |
| 탐지·방어 | 출처가 적고 패턴이 단순해 상대적으로 쉬움             | 출처가 분산되어 정상 사용자와 구분이 어려움             |

### 공격 유형 분류

DoS/DDoS는 무엇을 소진시키는가에 따라 세 가지로 나뉜다.

| 유형              | 소진 대상                                                       | 공격 방식                                                                                                                                                 | 대표 공격                           |
|-------------------|-----------------------------------------------------------------|-----------------------------------------------------------------------------------------------------------------------------------------------------------|-------------------------------------|
| 네트워크 대역폭   | 서버를 인터넷에 연결하는 회선 용량                              | 대량의 트래픽을 보내 회선 용량을 초과시킴. 악성 트래픽이 정상 트래픽을 압도해 사용자가 서버에 접근하지 못함                                               | ICMP Flood, UDP Flood               |
| 시스템 자원       | 네트워크 처리 소프트웨어의 자원. 임시 버퍼, 열린 연결 테이블 등 | 한정된 자원을 소비하는 특정 유형의 패킷을 보내거나, 처리 버그를 유발하는 구조의 패킷을 보냄. 소프트웨어 과부하 또는 다운이 발생해 재부팅 전까지 통신 불가 | SYN 스푸핑, poison packet           |
| 애플리케이션 자원 | 웹 서버, DB 등 애플리케이션의 처리 능력                         | 각각 상당한 자원을 소비하는 유효한 요청을 다수 전송. 다른 사용자의 요청에 응답할 능력이 제한됨                                                            | HTTP Flood, 대량 DB 질의, Slowloris |

### 방화벽으로 DoS/DDoS를 막기 어려운 이유

**방화벽은 트래픽이 허용 대상인지를 보고 접근제어를 하지만, DoS/DDoS는 허용된 방식을 과도하게 사용하여 공격**한다.

- 방화벽 앞단에서 문제가 발생: 대역폭 flooding은 액세스 링크 자체를 포화시켜 정상 패킷이 서버에 도달하지 못하게 만든다. 방화벽은 회선 안쪽에 있어서 액세스 링크 포화에 대응할 수 없다.
- IP 기반 정책의 한계: 출발지 주소 위조에 대응할 수 없고, DDoS의 경우 출처가 너무 많다.
- 열려 있어야 하는 포트는 닫을 수 없음: 공개 서비스 포트(80·443)는 애초에 차단 대상에서 제외된다. 80번 포트를 노린 공격에 그 포트 전체를 막으면 정상 서비스도 함께 중단된다.
- 정상 요청과 공격 요청의 구별이 어려움: HTTP Flood와 같은 공격은 패킷 형식도, 3-way handshake도 정상이다. 트래픽 급증이 평소보다 많은 사용으로 인한 부하인지 공격인지 분간하기 어렵다.

### 대응 방식

**DoS/DDoS는 완전히 예방할 수는 없고 완화하는 것이다.** 한 곳이 아니라 여러 위치에서 나눠 막는다.

| 위치                           | 방법                                                                                                                                                                                                                          |
|--------------------------------|-------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| 상위망 · ISP                   | 출발지 주소 위조 차단으로 반사 공격을 예방. 평시 비중이 작은 패킷 유형에 Rate Limiting. 외부발 IP 지정 브로드캐스트 차단                                                                                                      |
| 클라우드 · 스크러빙            | 표적으로 향하는 트래픽을 DNS 변경·터널링·프록시로 클리닝 센터에 경유시켜 악성만 분리. CDN·Anycast로 여러 거점에 분산                                                                                                          |
| 경계 장비 (방화벽 · IPS · DDS) | SYN 쿠키를 사용해 핸드셰이크가 끝날 때까지 서버 메모리를 쓰지 않음. 연결 테이블이 넘칠 때 미완성 항목을 선택적으로 폐기. 취약 포트 차단. DDS(연결 상태·요청 속도 등으로 DoS/DDoS를 빠르게 식별·차단하도록 만들어진 장비) 사용 |
| 서버 · 애플리케이션            | CAPTCHA로 사람과 자동화 공격을 구별. 요청률·연결 수 제한과 타임아웃 조정. 여러 사이트·네트워크로 서버를 복제해 부하를 분산                                                                                                    |

## IDS와 IPS

### IDS/IPS란

**IDS(Intrusion Detection System)는 컴퓨터나 네트워크 내 여러 영역에서 정보를 수집·분석해 보안 침입을 식별하는 시스템**이다.

**IPS(Intrusion Prevention System)는 IDS의 확장으로, 탐지된 악성 활동을 차단·예방하는 능력을 포함**한다.

전통적 방화벽은 허용된 경로인지만 판단할 뿐, 허용된 포트로 들어오는 내용물은 판단하지 않는다. 따라서 모든 패킷의 헤더를 보면서 심층 패킷 검사도 하는 장치로서 IDS/IPS가 필요하다.

### IDS와 IPS의 차이

**둘은 탐지 기술은 같고, 배치와 탐지 이후의 행동이 다르다.**

| 구분          | IDS                                                                        | IPS                                                            |
|---------------|----------------------------------------------------------------------------|----------------------------------------------------------------|
| 배치 / 트래픽 | 대역 외(Out-of-band). 복사본을 분석하고 실제 트래픽은 장치를 통과하지 않음 | 인라인(In-line). 실제 트래픽이 통과                            |
| 탐지 후 행동  | 경보 생성·로그 기록. 이후 사후 분석과 포렌식 진행                          | 패킷 폐기, 연결 리셋, 출발지 IP 차단                           |
| 성능·장애     | 지연 없음. 장비 장애가 통신에 영향 없음                                    | 지연·병목 가능. 통신 경로에 있어서 장비 장애 시 통신 중단 위험 |
| 오탐의 결과   | 잘못된 경보로 인한 분석 시간 낭비                                          | 정상 트래픽 차단으로 인한 서비스 장애                          |

### NIDS와 HIDS

IDS는 감시하는 위치에 따라 **네트워크 기반(NIDS)**과 **호스트 기반(HIDS)**으로 나뉜다.

| 구분      | NIDS (네트워크 기반)                                                             | HIDS (호스트 기반)                                                            |
|-----------|----------------------------------------------------------------------------------|-------------------------------------------------------------------------------|
| 감시 대상 | 특정 네트워크 세그먼트·장치의 트래픽. 네트워크·전송·애플리케이션 프로토콜을 분석 | 단일 호스트의 특성과 그 안에서 일어나는 이벤트(프로세스 식별자, 시스템 콜 등) |
| 설치 위치 | 네트워크 구간에 센서를 두고 트래픽 복사본을 받음                                 | 보호할 서버·PC마다 에이전트를 설치                                            |
| 분석 정보 | 패킷, 세션, 프로토콜                                                             | 시스템 콜, 감사(로그) 레코드, 파일 무결성 체크섬, 레지스트리 접근             |
| 장점      | 여러 시스템을 한 번에 감시하고 초기 단계의 침입 시도를 포착                      | 외부·내부 침입을 모두 탐지할 수 있음                                          |
| 한계      | 암호화된 내용과 호스트 내부 활동은 분석이 제한되고, 대량 트래픽에서는 성능 저하  | 호스트마다 설치·관리해야 하고 호스트 자원을 사용                              |

### 오탐과 미탐

탐지 결과는 네 가지 경우로 나뉜다.

|             | 실제로 공격                   | 실제로 정상                     |
|-------------|-------------------------------|---------------------------------|
| 판정 "공격" | TP (정탐): 공격을 올바로 탐지 | FP (오탐): 정상을 공격으로 오인 |
| 판정 "정상" | FN (미탐): 공격을 놓침        | TN: 정상을 올바로 판정          |

미탐은 IDS와 IPS 모두 공격을 통과시킨다는 점에서 같지만, 오탐의 대가는 서로 다르다.

- IDS의 오탐: 잘못된 경보. 분석 시간이 낭비되고, 경보가 잦으면 관리자가 경보 자체를 무시하기 시작한다.
- IPS의 오탐: 정상 트래픽 차단. 그래서 IPS 운영의 핵심은 보안성과 가용성의 균형이다.

**기저율 오류(Base-Rate Fallacy)는 기저율(전체 이벤트 중 실제 공격의 비율)을 무시하고, 탐지율만 보고 '경보는 대체로 진짜 공격'이라고 판단하는 오류**이다.

실제 침입은 드물기 때문에, 탐지되는 이벤트들 중 대부분은 오탐이다. 그렇다고 오탐을 줄이려고 공격으로 판정하는 기준을 엄격하게 하면 미탐이 늘어난다.

결론적으로, 시스템에서 늘 발생하는 정상 패턴을 예외 처리하여 오경보의 수를 줄이는 등 **서비스·네트워크 환경에 맞춘 지속적인 튜닝이 필요**하다.

### 마무리

네트워크 보안 장비를 직접 운영하는 건 보통 네트워크 엔지니어·DevOps·보안 인프라 담당자의 일이다.

보안 직무는 그 장비에 들어가는 정책이 유효한지, 정당성이 있는지, 올바르게 적용됐는지를 지속적으로 검토·관리하는 역할이다.

따라서 각 장비의 특징과 할 수 있는 일을 정확히 아는 것이 정책 검토의 기초가 된다.
