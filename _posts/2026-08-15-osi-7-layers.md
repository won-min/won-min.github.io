## 요약

1. OSI 모델은 ISO가 만든 개념 모델·참조 모델이고, 목적은 벤더 간 호환성 확보를 통하 비용 절감이다

2. 각 계층은 위에 기능을 제공하고 아래에서 서비스를 받으며, 데이터는 내려가며 헤더가 붙고 올라가며 벗겨진다.

3. 실제 인터넷은 TCP/IP 4계층으로 돌아가지만, OSI는 장애 지점을 계층별로 좁혀가는 사고 틀로서 유용하다.

## OSI 7 계층이란 무엇인가?

### 개념 모델이자 참조 모델

OSI 모델은 ISO(국제표준화기구)가 만든 **개념 모델**이자 **참조 모델**이다.

- **개념 모델**: 실제로 구현된 제품이 아니라, 통신이라는 과정을 이해하기 위해 만든 추상적인 구조.
- **참조 모델**: 서로 다른 집단이 만든 장비와 소프트웨어가 호환되도록, 모두가 공통으로 참고하는 기준.

이 모델은 **통신 시스템을 7개의 추상화 계층**으로 나눈다. 그리고 각 계층은 **바로 위 계층에 기능(function)을 제공**하고, **바로 아래 계층에서 서비스(service)를 받는다**는 원칙을 따른다.

### OSI 7 계층이 만들어진 목적

표준이 없던 시절에는 기준이라 할 만한 것 자체가 없었다.  
같은 회사 장비끼리는 호환이 잘 됐지만, 다른 회사 장비 사이에서는 문제 생기면서 **시간·인력·비용의 낭비**가 발생했다.  
ISO는 **네트워크 제품들 간의 호환성을 확보**해서 위 낭비를 없애기 위해, 국제표준으로 참조 모델을 제정했다.

궁극적인 목적은 **비용 절감**이다. 그리고 7개로 세분화하면서 두 가지 효과가 발생했다.

- **문제 지점을 빨리 찾을 수 있다.** 계층이 뭉쳐 있으면 장애가 났을 때 어디서 난 것인지 찾는 데 시간이 오래 걸리는 반면, 계층이 나뉘어 있으면 문제 발생 지점의 범위를 좁혀 갈 수 있다.
- **가르치기 쉬워진다.** 계층이 나뉘어 있기에 학습에 유리하다.

### 캡슐화

모든 계층에는 공통적으로 캡슐화가 적용된다.

- **캡슐화**: 데이터를 보낼 때 위 계층에서 아래 계층으로 내려가며 계층마다 자기 헤더를 덧붙인다.
- **역캡슐화**: 받을 때는 반대로 아래에서 위로 올라가며 헤더가 하나씩 벗겨진다.

브라우저에 "https://example.com"을 입력했을 때, 각 계층이 하는 일은 아래와 같다.

| 계층 | 하는 일                                                            |
|------|--------------------------------------------------------------------|
| 7    | GET / HTTP/1.1, Host: example.com 요청을 생성한다                  |
| 6    | 그 데이터 전체를 TLS로 암호화해 감싼다                             |
| 5    | (실제 구현에서는 다른 계층에 흡수되어 별도 단계로 드러나지 않는다) |
| 4    | 위 전체를 목적지 포트 443으로 감싼다                               |
| 3    | 위 전체를 목적지 서버 IP로 감싼다                                  |
| 2    | 위 전체를 다음 장비의 MAC 주소로 감싼다                            |
| 1    | 완성된 비트열을 전기·전파 신호로 변환해 내보낸다                   |

## 계층 별 주요 특징

### 각 계층 요약

| 계층 | 이름        | 전송 단위                       | 역할                                           | 프로토콜/장비           |
|------|-------------|---------------------------------|------------------------------------------------|-------------------------|
| 7    | 응용        | 데이터 · 메시지                 | 사용자 데이터와 직접 상호작용                  | HTTP, FTP, SMTP, DNS    |
| 6    | 표현        | 데이터 · 메시지                 | 인코딩 변환 · 암호화 · 압축                    | TLS(애매)               |
| 5    | 세션        | 데이터 · 메시지                 | 세션 수립·유지·종료                            | RPC                     |
| 4    | 전송        | 세그먼트(TCP) / 데이터그램(UDP) | 포트 기반 다중화·역다중화, 흐름·혼잡·오류 제어 | TCP, UDP                |
| 3    | 네트워크    | 패킷                            | 다른 네트워크로 전달, 라우팅                   | IP, ICMP, 라우터        |
| 2    | 데이터 링크 | 프레임                          | 노드 대 노드 전달, 오류 검출                   | Ethernet, Wi-Fi, 스위치 |
| 1    | 물리        | 비트                            | 비트 ↔ 전기·전파·광 신호                       | 케이블, 허브, 리피터    |

### 7계층 - 응용 (Application)

**사용자 데이터와 직접 상호작용**하는 유일한 계층이다. 우리가 실제 사용하는 여러 프로그램, 서비스들이 7 계층과 연관되어 있다.

이때, 브라우저나 메일 클라이언트 같은 프로그램 자체가 이 계층인 것은 아니다**.** 그 프로그램이 통신을 시작할 때 의존하는 **통신 규약과 제공 기능**이 이 계층에 속한다.

주요 기능에는 파일 공유, 메시지 처리, 데이터베이스 접근 등이 있다.

### 6 계층 - 표현 (Presentation)

위 계층인 응용 계층이 바로 쓸 수 있도록 **데이터를 준비하는 계층**이다. 역할은 크게 세 가지다.

- **인코딩 변환**: 인코딩 방식이 다른 기기끼리도 문자가 깨지지 않도록 변환한다.
- **암호화 / 복호화**: 보낼 때 암호화하고, 받을 때 복호화한다.
- **압축 / 해제**: 전송량을 줄이기 위해 압축하고, 받는 쪽에서 해제한다.

이때, HTTPS에 쓰이는 TLS는 암호화라는 표현 계층의 성격과 연결이라는 전송 계층의 성격을 모두 갖고 있어서, OSI 모델의 한 계층에 깔끔하게 들어맞지 않는다.

### 5 계층 - 세션 (Session)

세션은 **통신을 시작해서 유지하고 종료하기까지의 일련의 과정**을 말한다. 따라서 세션 계층은 둘 이상의 응용 프로세스 사이에서 연결의 **개시 → 유지 → 종료**를 담당한다.

- **동기점(sync point)**: 전송 중간중간 "여기까지 왔다"는 표식을 찍어 둔다.
- **재동기화**: 문제가 생기면 합의된 동기점으로 세션을 되돌린다. 다만 그 지점의 상태를 실제로 복구하는 책임은 세션 계층에 없다.
- **토큰 관리**: 어느 쪽이 말할 차례인지를 명시적으로 제어한다.

토큰에는 데이터 토큰, 동기 토큰, 종료 토큰, 활동 토큰이 있다.

이때, 전송 모드에 따라 데이터 토큰의 필요 여부가 갈린다.

- 전이중: 양쪽이 동시에 전송 가능. 데이터 토큰 불필요.
- 반이중: 한 번에 한쪽만 전송 가능. 데이터 토큰 필요.

### 4 계층 - 전송 (Transport)

전송 계층은 **종단 간(end-to-end) 통신**을 담당한다.

한 대의 컴퓨터 안에서도 여러 프로세스가 동시에 돌아간다. 그래서 도착한 데이터를 어느 프로세스에게 줄 것인지 식별해야 하고, 그 역할을 **포트 번호**가 한다. 포트는 하나의 컴퓨터 안에서 "어느 프로그램과 통신할 것인가"를 지목하는 16비트 번호다.

- **다중화**: 보내는 쪽에서 수행한다. 각 프로세스의 데이터에 출발지 포트와 목적지 포트를 헤더로 붙이고 하나로 합친다.
- **역다중화**: 받는 쪽에서 수행한다. 도착한 세그먼트의 헤더에서 목적지 포트를 읽고 해당 프로세스에게 전달한다.

다음으로 전송 계층에서 **신뢰성 제어**를 TCP는 제공하고 UDP는 제공하지 않는다. 신뢰성은 이 계층의 의무가 아니다. 영상 스트리밍이나 실시간 게임, 인터넷 전화는 패킷 몇 개를 잃는 것보다 늦게 도착하는 것이 더 치명적이기 때문에. 일부 손실을 감수하고 일부러 UDP를 사용한다. TCP에서는 아래 항목을 통해 신뢰성 제어를 수행한다.

- **흐름 제어**: 빠른 송신자가 느린 수신자를 압도하지 않도록 전송을 조절한다.
- **혼잡 제어**: 송신자와 수신자 사이 네트워크의 혼잡을 감지해 전송률을 조절한다.
- **오류 제어**: 확인응답과 재전송으로 누락된 것을 복구한다.

TCP와 UDP를 비교해 보면 아래와 같다.

| 항목          | TCP                                                | UDP                         |
|---------------|----------------------------------------------------|-----------------------------|
| 연결 방식     | 연결 지향 — 3-way 핸드셰이크 (SYN → SYN-ACK → ACK) | 비연결형                    |
| 신뢰성 / 순서 | 확인응답·재전송으로 보장, 순서 보장 O              | 보장하지 않음, 순서 보장 X  |
| 데이터 처리   | 세그먼트로 분할·재조립                             | 분할 없이 그대로 캡슐화     |
| 헤더 크기     | 최소 20바이트 (포함 최대 60)                       | 고정 8바이트                |
| 용도          | 웹, 파일 전송, 메일                                | 스트리밍, 실시간 게임, VoIP |

### 3 계층 - 네트워크 (Network)

**서로 다른 네트워크에 연결된 노드 사이로 패킷을 전달**하는 계층이다. 아래와 같은 주요 특징을 지닌다.

- **논리 주소(IP) 지정**: 장비에 새겨진 물리 주소(MAC)와 달리, 네트워크상의 위치에 따라 부여되는 주소다.
- **라우팅**: 출발지에서 목적지까지의 최적 경로를 설정한다. 실제로 이 역할을 수행하는 장비가 라우터다.
- **단편화**: 링크로 내보내기에 데이터가 너무 크면 조각내고, 반대편에서 재조립한다.
- **비연결형·최선노력(best-effort) 전달**: 손실, 순서 뒤바뀜, 중복 도착을 모두 허용한다. 이것을 어떻게 신뢰성 있게 만들지는 4 계층의 몫이다.

### 2 계층 - 데이터 링크 (Data Link)

데이터 링크 계층은 **같은 네트워크 안에서 바로 옆 노드까지(node-to-node)** 전달한다. 아래와 같은 주요 특징을 지닌다.

- **물리 주소(MAC 주소) 지정**: 장비 자체에 부여된 주소를 사용한다.
- **오류 검출과 정정**: 1계층인 물리 계층은 신호를 나를 뿐 오류를 알지 못한다. 링크 계층에서 그 오류를 검출하고 경우에 따라 정정한다.
- **흐름 제어**: 링크 구간에서의 전송 속도를 조절한다.

### 1 계층 - 물리 (Physical)

지금까지 쌓인 모든 헤더와 데이터 비트가 **전기·전파·광 신호로 변환**되어 케이블과 공기를 타고 전송된다.

이 계층에서 **신호 규칙의 합의**는 필수적이다. 예를 들어 전압이 0V에서 5V로 올라가면 1, 내려가면 0으로 읽자고 양쪽이 미리 정해놔야 한다.

**전송 모드**도 이 계층에서 정의한다.

- 단방향: 한쪽만 전송할 수 있다
- 반이중: 양쪽 다 가능하지만 한 번에 한쪽만 가능하다
- 전이중: 양쪽이 동시에 전송할 수 있다

이 계층에서의 장애는 물리적이다. 예시로 케이블 불량, 노이즈 간섭, 고장 난 랜카드 등이 있다.

## OSI vs TCP/IP

**실제 인터넷은 OSI가 아니라 TCP/IP 구조**로 돌아간다.

TCP/IP는 OSI의 위쪽 세 계층을 Application 하나로, 아래쪽 두 계층을 Network Access 하나로 합친 형태다.

그럼에도 OSI 7 계층을 배우는 이유는, 문제가 계층별로 구분되어 있어 **장애가 발생했을 때 원인을 좁혀 가는 사고의 틀**로 쓸 수 있고 네트워크 통신을 학습하는데 용이하기 때문이다. 실무에서 OSI 모델은 구현물이 아니라 개념적 도구로 사용된다.
